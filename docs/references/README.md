# Visual references

References are for analysis and moodboarding, not direct copying. Historical
inspiration may include Tracy, Alter Ego, Alien, The Dream Machine, early
interactive fiction, vintage AI/multimedia systems, scientific terminals and
low-resolution digitized imagery. Do not assume any particular edition or asset
is available for reuse.

For each reference, create a short Markdown entry with:

- Title, creator/publisher if known, date/version/platform if known.
- Source URL or bibliographic/source description, and access date.
- Relevant screen, sequence or timecode and where the private material is stored.
- What matters: portrait treatment, negative space, palette behaviour, motion
  frequency, typography density, border geometry or sound character.
- Why it supports PROJECT 2186's presence, restraint or alternative-history computing.
- What to reinterpret and what to avoid; distinguish observation from proposal.
- Rights/license information if known and attribution requirements for any intended reuse.

A useful note is specific: “long portrait stillness makes a single gaze change
noticeable” gives an actionable principle. “Make it retro” does not.

Private screenshots, recordings and moodboard files may live in
`docs/references/_private/`, which is gitignored. Keep analysis notes in the public
documentation where appropriate. Gitignore does not encrypt files or establish
reuse rights; do not force-add private material. A fresh checkout will not contain
those assets. Palette, typography and portrait decisions should be reviewed with
the author after reference analysis, before visual implementation.
